# SITE.md — 情報設計のSource of Truth

このファイルは、AIの鉄人株式会社コーポレートサイトの**情報設計**（Sitemap / 各ページの目的・Target・CTA・Section構成 / ナビゲーション / URL / meta方針 / ページ間導線）のSource of Truthである。Phase 2（Information Architecture）の成果物。

- **上位ドキュメント**: 作業ルールは `CLAUDE.md`、見た目は `DESIGN.md`、事実は `docs/CONTENT.md`。**同じ内容を二重に書かない。**
- **このファイルが決めること**: ページが何のために存在し、誰に向けて、どの順序で、何を並べるか。
- **このファイルが決めないこと**: 具体的な文言（→ `docs/CONTENT.md`）、色・余白・コンポーネントの見た目（→ `DESIGN.md`）、語彙・トーン（→ `docs/BRAND.md`・未作成）。
- **実装状況**: 本ファイルは設計であり、**現時点で実装済みのページは `/`（1ページLP）のみ**である。下層ページは Phase 4〜6 で順次実装する。

---

## 1. 設計方針

現行の1ページLPから、**コーポレートサイト型のマルチページ構成**へ移行する（計画書 §10）。方針は次の3点。

1. **実績を最上位の資産として扱う。** 実績がサイト後半まで出てこない構成を廃止し、トップページのファーストビュー直後に置く。ケーススタディを独立ページ化し、サイトの中心コンテンツに格上げする（計画書 §2.2 / §3-3 / §11-02 / §12）。
2. **営業LP型の導線を廃止する。** 「課題があります → こう解決します → サービスがあります」という順序をやめ、「何者か → 実績 → どう進めるか → 何を提供するか → 誰がやるか」の順に組み替える（計画書 §2.2 / §11）。
3. **1ページ1目的。** 各ページに主CTAを1つだけ置き、副CTAは次に見るべきページへの誘導に使う（`DESIGN.md` §6.2「主CTAは1画面に1つ」）。

### Target（全ページ共通）

| 区分 | 想定 | 主な関心 |
| --- | --- | --- |
| **経営者** | 中小・中堅企業の社長・役員 | 投資対効果、任せられる相手かどうか、他社の実績 |
| **DX担当者** | 情報システム・企画・推進担当 | 進め方の具体性、自社で回せるようになるか、支援範囲 |
| **地域企業** | 群馬をはじめとする地方企業 | 現場に来てくれるか、自社の業種で通用するか |

各ページ定義の「Target」欄には、そのページで**特に重視する読み手**を記す（3者すべてを毎ページ均等に扱わない）。

## 3. 共通要素

### 3.1 グローバルナビゲーション

| 表示ラベル | リンク先 | 備考 |
| --- | --- | --- |
| SERVICE | `/service/` | |
| CASE | `/case/` | |
| COMPANY | `/company/` | |
| NEWS | `/news/` | 【要確認 T-28】確定・公開まで**項目を出さない** |
| CONTACT | `/contact/` | |

- **主CTAボタン**を右端に置く。文言は `docs/CONTENT.md` §6.2 の「AI活用について相談する」。リンク先は `/contact/`（Googleフォームへの直リンクではなく、まず自社ページへ着地させる）。
- ラベルは英字大文字。日本語の補助ラベルを併記するかは `DESIGN.md` の管轄。
- 現行の**ページ内アンカー（`#service` 等）は廃止**し、すべてページ遷移にする。
- `≤768px` はハンバーガーメニュー（`DESIGN.md` §6.7）。
- ロゴ（`assets/img/logo-horizontal.png`）は常に `/` へのリンク。

### 3.2 フッター

3ブロック構成にする。

1. **会社情報**: ロゴ / 社名 / 所在地 / MAIL（`docs/CONTENT.md` §1）
2. **ナビゲーション**: SERVICE / CASE / COMPANY / NEWS / CONTACT（グローバルナビと同じ項目）
3. **ユーティリティ**: PRIVACY（`/privacy/`）/ コピーライト「© 2026 株式会社AIの鉄人」

- SNSアカウントは**確認できていないため置かない**（`docs/CONTENT.md` に記載がない事実は載せない）。
- フッターにも問い合わせ導線を1つ置く（テキストリンクで可。主CTAボタンをフッターにも重複配置しない）。

### 3.3 CTAの階層

| 階層 | 用途 | 配置ルール |
| --- | --- | --- |
| **主CTA** | AI活用について相談する（→ `/contact/`） | 1ページに1つ。ヘッダーとページ末尾のCTAブロックに置く |
| **副CTA** | 導入事例を見る / サービスを見る 等（サイト内回遊） | 各セクション末尾に最大1つ |
| **最終導線** | Googleフォーム（お問い合わせ・資料請求） | `/contact/` にのみ置く。`target="_blank" rel="noopener"`（`docs/CONTENT.md` §6.1） |

- **抽象的な「お問い合わせ」を主CTAの文言に使わない**（計画書 §11-09）。
- 資料請求はお問い合わせと同一のGoogleフォームを使う。資料はフォーム送信後にメールで送付する運用のため、「ダウンロード」という語を使わない。

### 3.4 meta の方針

具体的な文字列は `docs/CONTENT.md` の事実に従って各ページ実装時に確定する。ここでは**パターンだけ**を決める。

| 項目 | 方針 |
| --- | --- |
| `title` | `{ページ固有の要約}｜株式会社AIの鉄人`。区切りは全角パイプ `｜`。**トップのみ**は `株式会社AIの鉄人｜{提供価値の要約}` の順（社名を先頭に置く）。全角30〜35文字を目安に、検索結果で切れない長さにする |
| `description` | 全角100〜140文字。**ページごとに固有の文にする**（全ページ同一文を使わない）。そのページで扱う事実だけを書く。誇張・未確定の数値を入れない |
| `canonical` | 末尾スラッシュ付きの絶対URL（例: `https://www.ainotetsujin.com/case/fuji-subaru/`） |
| `og:title` / `og:description` | 原則 `title` / `description` と同一 |
| `og:type` | トップ・下層ページ = `website`、ケーススタディ詳細・ニュース記事 = `article` |
| `og:image` | 専用OG画像（1200×630）。【要確認 T-04】確定までは `assets/img/logo-circle.png` を絶対URLで指定 |
| `twitter:card` | `summary_large_image` |
| `favicon` | `assets/img/logo-circle.png` |
| `theme-color` | `DESIGN.md` の背景色トークンに合わせる（Phase 3 で確定） |
| 構造化データ | トップ: `Organization` + `WebSite`。下層: `BreadcrumbList`。ケーススタディ詳細: `Article`。**値は `docs/CONTENT.md` の事実のみ**。`aggregateRating` 等、裏付けのない型を使わない |

### 3.5 URL・ファイル構成の規約

- **ディレクトリ + `index.html`** 形式（例: `/service/index.html`）。URLは末尾スラッシュで統一する。
- 英小文字・数字・ハイフンのみ。アンダースコア・日本語URLを使わない。
- 顧客名を含むURLは、**掲載許諾の範囲内**で使う（`/case/fuji-subaru/` は【要確認 T-03】の対象）。
- 現行の `/` はアンカーリンクを持つ1ページ構成である。マルチページ化にあたり、**旧アンカー（`https://www.ainotetsujin.com/#service` 等）は外部から参照されている可能性がある**。トップページ側で該当セクションを維持するか、リダイレクトの代替（トップ内の対応セクションを残す）を検討する。GitHub Pages は静的配信のためサーバーサイドリダイレクトを使えない。
- **ページを増やしたら `sitemap.xml` を必ず更新する。**
